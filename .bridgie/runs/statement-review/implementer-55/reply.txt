- **The features:** `--feature acquirers|director|cash|lenders|two_accounts`, repeatable, or `all`.
  - Real acquirer and gateway payouts (SumUp, Stripe) and a delivery platform (Deliveroo). One SumUp payout is four times the usual, so the irregular-acquirer indicator flags it.
  - Director funding, once by a name the case profile lists and once by "DIRECTOR LOAN" wording.
  - Weekly cash deposits below the £2,500 limit, one deposit at £3,200, and £1,450 paid in two days after a £1,500 withdrawal.
  - A named lender's drawdown and its monthly repayments.
  - A second "reserve" account, written beside the main statement as `STEM_reserve.csv`. The profile names both accounts, so transfers between them are own-account transfers.
- **Byte identity:** feature lines come from their own random generator and are only added when a feature is asked for. The new truth fields are left out of the truth file when there are none, so existing truth files are unchanged too. The check runs against hashes taken at 25a943c, before the change (`tests/golden/synth_archetypes.sha256.json`).
- **Truth is for v2 only.** Feature truth is what the v2 rule table gives with the generated case profile, since only v2 knows real acquirers and cash. With features on, the existing "capital introduced" line's truth is `director_funding`, as v2 gives it.

- **Tests:** in `tests/test_synth_features.py`. The P17 invariant tests, including the byte-identity check, run by name with `-m invariants -k p17` (40 pass). There are two contract tests: one for the CLI, and one showing the evals report a truth that disagrees.

- **No own-account pairing:** pairing transactions across the two accounts (R8) is Tier 2 and not built. The reserve account is checked as its own statement, and P17 claims nothing about pairs.
- **Short statements:** for 1–3 month statements, the late-VAT count is 0 in truth while M13 is n/a. This happens with or without features, so it was already there. The evals and tests use 6 months or more.
