I reproduced the reviewer's main finding and it is fixed at `b161b7c`: a sign-off cut short by a full disk can now be repaired and signed off again. After the hardening commit I reran only the contracts tier and `tests/test_signoff.py`, not the full suite.

**The finding.** If the disk fills after part of the sign-off line is written, the log is left with an unfinished (torn) entry after the pack-write entry. Before this fix, every later sign-off was refused and nothing in the tool could clear it. I reproduced that with the real append code and a write that stops after ten bytes. Now `cma case sign` refuses with exit 3 and tells you to run `cma case repair` (`src/cma/cli.py:802`). That command drops the unfinished entry once a person types their name to confirm. The next sign-off then records the sign-off already in the pack's `evidence.json`, without rewriting the pack. The reviewer's other point, that no production code removed a torn entry, is closed by the same command.
