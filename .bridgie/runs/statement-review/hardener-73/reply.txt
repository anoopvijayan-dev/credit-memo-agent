**Fixed:**
1. **Half-made cases.** Before, if the profile update or an import failed after `synth.to_case` had made the case, a half-imported demo case stayed behind. Now `to_case` removes the case it made, the same way `new_case` already cleans up after itself.
2. **Refusals shown as tracebacks.** `cma generate --case` only caught `CaseStoreError`, so a case-log refusal (for example, another window holding the case) reached the user as a Python traceback. It now uses the same error handling as the other case commands, with the same exit codes.
3. **Sync-folder warning.** When the case root is in a OneDrive-style sync folder, the warning now goes to stderr before the case is made, as `cma case new` does, instead of being raised as a Python warning.
