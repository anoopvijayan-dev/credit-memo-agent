I went through every checklist line for T12's case log and made three small fixes. They are committed as `5729392` on the task branch. All 70 case-log tests and the full suite pass (289 passed, 5 skipped), and lint is clean.

**Fixes made in this run:**
- **Dropping a torn last entry is now all-or-nothing.** Before, the code cut the log and then wrote the "dropped" record as two separate steps. A crash between them left a clean log with no record of who dropped the entry. Now the trimmed log and the record are written to a temporary file that replaces the log in one step. A test simulates a crash at that step and checks the log is left exactly as it was.
- **Entry data with NaN or Infinity is now refused.** These were being written as values that are not valid JSON. A verifier written in another language could not re-hash them.
- **The folder is now synced to disk when the log is created or replaced.** Without this, the log file itself could be lost in a power cut even though its contents were written.

**Checked against the checklists:**
- A retried append that already succeeded is refused as a conflict and writes nothing.
- A second writer is refused, both in the same process and from another process.
- New log and lock files are readable only by their owner, and error messages name entries by number without quoting their content.
- Speed: at 2,000 entries (730 KB), verifying the chain takes 15.7 ms and an append 16.0 ms.
- No new dependencies, and nothing else in the repo imports the module yet, so rolling back means reverting the commit.

**Gaps for the owner (in `notes`, not changed):**
1. Deleting the last entry, or cutting the log back to an earlier point, can't be detected from the file alone. Sign-off and the pack need to record the log's last position and hash and check them later.
2. A read taken without the writer lock can catch another writer mid-line and wrongly report a torn entry. Sign-off must check the log while holding the lock.
3. The Windows locking code has not been tested; it needs a Windows CI run before a pilot on the firm's machine.
4. There is no limit on entry size.
5. Nothing yet shows a broken log to the user: the red banner, error exit and confirm-to-drop prompt belong to the workspace, sign-off and report tasks.
6. Making the case root folder private is case-root work, not done by the log.
7. The repo has no changelog for a release-note line.
