I built T12, the case log, in a new module `src/cma/case.py`, with 67 tests in `tests/test_case_log.py`. The full suite (286 passed, 5 skipped) and `ruff` both pass. Nothing is committed, `.bridgie/` is untouched, and the verifier still has to accept it.

- **Hash chain (R42):** the log is one JSON line per entry. Each entry carries the hash of the entry before it and its own hash.
- **Tamper detection (P15):** the tests try every possible change on logs of 2 to 6 entries, so each case is checked rather than sampled. Changing any field of an entry before the head, removing one, adding one or swapping two is caught on the next load, and the first bad entry is named by number. If someone edits an entry and recomputes its hash, the next entry is the one named, because its link to the edited one no longer holds.
- **Torn last entry (R43):** a last line without its newline is reported as an unfinished write, not as tampering, and is named. Nothing more can be added to the log until someone confirms dropping it with their name, and that drop is itself logged. `require_intact()` refuses with the first bad entry named, and sign-off is meant to refuse when it does.
- **One writer at a time:** a second writer, in the same process or another one, is refused straight away. A write based on an out-of-date position is refused as a conflict and writes nothing. If the program crashes, the operating system releases the lock.
- **Error messages** give the entry number only, never what the entry contains.

Limits:
- **Removing the newest entry can't be detected from the file alone.** P15 only covers entries before the newest one. A sign-off or pack should record the log's position and newest hash at that moment, so a later removal can be spotted.
- **Nothing uses the log yet.** Imports, overrides, previews, packs and sign-off come in later tasks (T13, T16, T23, T27). Those have to write through this log and check `require_intact()` before accepting a sign-off.
- **The Windows lock path has not been run.** Only the Linux path is tested.

I ran the tests in a temporary environment in my scratch folder, because the system Python lacks the project's dependencies.
