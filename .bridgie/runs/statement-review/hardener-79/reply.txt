I went through every checklist item for T39 (`cma pseudonymise`). The existing build already met most of them. I closed one gap in code: a failure partway through writing the output folder could leave a partial copy behind. That fix is committed as 92e28ee. The full suite passes (3000 tests), as do ruff over `src` and `tests`, compileall, and the 28 pseudonymise tests.

- **Fixed:** `write()` now writes the copy into a staging folder beside `--out` and renames it into place. If anything fails partway, such as a full disk, the staging folder is removed and nothing appears at `--out`. A new test injects that failure and checks the next run starts clean.
- **Added tests:**
  - Two runs on the same input give identical files.
  - The output folder is owner-only and each file is too.
  - None of the written files contains the original names or account numbers.
  - A refusal names lines and figures but never quotes description text.
- **Gap 1, owner decision:** `--out` can point inside the repository at a folder git does not ignore. The copy is still personal data, so it could be committed. The case store refuses that (R31) and this command does not. Fixing it means deciding whether R31 covers this command, so I left it out of the code.
- **Gap 2, performance:** the command runs at roughly 5 ms per line (about 5 seconds for 1,092 lines), so a 10,000-line statement would take around a minute. No target is set for this command.
- **Gap 3, operability:** this command adds no case-log entry, alert or runbook. It runs locally, one-off, and refuses by exit code, which follows the design's "refuse, don't alert" approach.
