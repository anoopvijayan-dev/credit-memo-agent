The four minor findings:

1. **Non-money differences can be rounded** (`src/cma/metrics.py:1284`). Python's default decimal precision is 28 digits, and the 40-character input cap lets an underwriter type more than that, so the difference can lose digits. Money is not affected because it uses whole pence.
2. **The page form offers months an account doesn't have** (`src/cma/review/compare.py:194`). On a multi-account case the month list comes from the combined summary for every account. Picking an account that doesn't cover the chosen month gives "No such monthly cell."
3. **Two test claims go beyond their proofs** (`tests/test_compare.py:174`). The exactness test covers about ±£100bn, not the claimed ±£10tn. The combined-case test only checks the possible own-account lines, and overridden lines in the combined view are untested. From reading the code, both behaviours are correct, so this is a gap in coverage, not a bug.
