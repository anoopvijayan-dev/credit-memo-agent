I've built T16, the override log. The P3 and P4 tests pass, and so does the full suite, though I ran that just before a one-line lint fix and only reran the related tests afterwards. The changes are not committed.

**What it does**
- **Recording an override:** each one goes to `overrides.jsonl` in the case folder, readable only by the owner. It holds the account, the line, the old and new category, the reason, the typed name, the OS user, the UTC time and the hash of the statement file. It is written while holding the case, with a case log entry that carries the record's hash.
- **What is refused:**
  - a category not valid for the line's direction: a credit's must have a money-in bucket, a debit's must not be a money-in-only one;
  - a line that isn't in the case, an unknown category, or an empty reason or name;
  - any attempt to change a line's amount, date, balance or description;
  - a stale expected log position, which is a conflict.
  If the case log refuses the entry, the record is taken back. An override to the category the line already has records nothing.
- **Tampering:** a record edited by hand is refused, naming it. A record the case log never recorded is ignored as a leftover and dropped by the next write.
- **Stale overrides:** an override whose line is gone, or whose statement hash has changed, is not applied. It is listed as stale until confirmed or dropped. Confirming re-records it against the current statement, and is refused when the line is gone, so that kind can only be dropped. For each line the latest override decides.
- **Figures:** they are recomputed every time from the statements, the profile and the whole override log. Each figure and monthly cell that rests on an overridden line is marked.
- **CLI:** `cma case override`, `cma case overrides`, `cma case resolve-override --confirm|--drop` and `cma case figures`. The last prints `*` beside marked figures and lists stale overrides.

**Choices I made that a reviewer may question**
- A figure is marked if an overridden line is among its lines, or if its value or lines differ from the same calculation with no overrides. So unexplained money in (M25) is marked when a credit leaves it, even though that line is no longer in its evidence.
- The case log entry carries every field except the reason. The reason stays in `overrides.jsonl`, tied to the entry by the record's hash.

**Not covered**
- Figures are computed per account, each statement on its own. Combining a case's accounts is R41, which is Tier 2.
- Indicators and the policy check are not recomputed here. That is left to T22's workspace, which can build on this.
