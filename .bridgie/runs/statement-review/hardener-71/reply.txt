I hardened T33: I added two tests, the existing suite passes, and five gaps need your decision. The new tests are in commit `90d4969`, in `tests/test_multi_account.py`:
- **Import order:** the same accounts imported in a different order give the same pairing.
- **Protected credit:** a lending drawdown is never paired, so it stays in lending drawdowns.

**Test results:** the multi-account file passes, 27 tests including the two new ones. The full suite passed (2,687 tests) and ruff passed before I added them; I re-ran ruff and the file afterwards, but not the full suite.

**Checklist, with proof in `claim.json`:**
- **Idempotency:** importing the same file twice changes nothing. An import refused at the combined limit writes nothing to the case.
- **Access:** the new combined-figures page refuses requests without the session token. An override against the combined view is refused.
- **Migration and rollback:** no stored data changes, and a one-account case takes no new code path. Rollback is a reinstall with nothing to repair.
- **Speed:** on a 10,000-line case split across two accounts, recomputing after an override took 1.2 s and the case page took 1.67 s, under the 2-second target. The first cold call took 2.79 s because it loads the rules. This was a one-off script, not a test the runner runs.

**Gaps that need your decision:**
1. **Pairing window:** R8 says "within the configured days", but the window is fixed at 3 days in code and no config file exposes it.
2. **Silent pairing:** a supplier payment in one account and a trading credit of the same amount within 3 days in another become own-account transfers. They leave trading receipts with no warning. The design intends this and it can only lower trading receipts, but nothing flags it.
3. **No log line:** only the line's recorded rule shows that a pairing ran. That matches the local-only design.
4. **Docs:** neither the README nor the design records the `pairing:<account>:<id>` rule form or the "All accounts" section of the workspace.
5. **Speed coverage:** the 2-second checks the runner runs cover only one-account cases.
