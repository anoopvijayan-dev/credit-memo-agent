T24 fails review. R27 and P20 pass, but P14 fails: a case with two or more accounts gets an ungrounded preview whenever an account key has a digit in it. I couldn't write `evidence.json` to the run directory because the write was blocked, so the full evidence is in the block below. I also couldn't run Python to reproduce the defect; I found it by reading the code.

**The P14 defect (major).** When a case has more than one account, the memo text starts each account's sentences with `Account {key}: ` and adds a `### Account {key}` heading (`src/cma/pack.py`, `_text`). Account keys may contain digits (`src/cma/store.py:64`). The grounding guard reads the digit in a key like `2` or `hsbc-1` as a number with no figure id after it, so it flags it. The preview is then ungrounded and no pack can be signed off (R28). P14 requires the text to pass the guard for any case. The P14 tests ran and passed, but they only use the keys main, spare, other and the synthetic ones.

**Two minor findings:**
- **Judgement fields:** the packaged `memo_fields.yaml` says credit history and key risks never map a figure, but the code only enforces that for `recommendation`. A firm map can also give the recommendation another id and get past the check.
- **Wheel claim:** the claim that the built wheel carries the field map rests on the producer's manual check; no runner tier proves it.
