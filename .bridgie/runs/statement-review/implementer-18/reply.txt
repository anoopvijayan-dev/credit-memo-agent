**Fixed:**
- **Head file.** Each append now also writes `log.jsonl.head`, holding the entry count and the last entry's hash, after the log line is safely on disk. Every load checks the chain against it. This now catches a chain fully rebuilt after a change, removal or reorder, a removed head entry, entries added past the recorded head, and a missing or unreadable head file.
- **Crash between the two writes.** If power is lost after the line is written but before the head file is updated, the last entry is reported as incomplete (not as tampering) and can be dropped with the person's name recorded. A reader without the lock looks again for about 0.1 s first, so it doesn't report this while a write is still in progress.
- **Data race.** `append` now writes a private copy of the caller's data, so a change to the caller's dict mid-append can no longer leave a broken entry. Before writing, each line is checked the same way a reader will check it.
- **Test marking.** Every P15 test now has `@pytest.mark.invariants` and `p15` in its name, so the runner's invariants tier picks them up: 69 passed, where it previously selected none.

**Not fixable here:** nothing calls the log yet, so no case action is recorded and no sign-off refuses a broken log. Those actions (case store, overrides, preview, pack, sign-off, case import, firm-rule promotion) don't exist on this branch. They are built in T13, T16, T24, T25, T27, T28 and T37, which depend on T12. Wiring them now would mean inventing their interfaces. I've recorded both findings as reproduced and suggested in `notes` that R42 and R43 be judged on those tasks.

**Limits of the head file:**
- It holds only the count and the last hash. When a rebuilt chain doesn't match, it names the entry at the recorded count ("rewritten at or before this entry"), which may not be the first entry changed.
- Someone who rewrites the log and the head file together can't be caught from these files alone. Sign-off and the pack should record the head they saw.
