**New problem: caller-turned-on tracing is never switched off.**
- **What happens:** a caller wraps a run under the lock in LangChain's `tracing_v2_enabled()`, for example `with tracing_v2_enabled(): build(llm.FakeLLM()).invoke(...)` with `offline_lock: true`. The run is still traced to LangSmith.
- **Why:** the code switches tracing off with `langsmith.tracing_context(enabled=False)` (`graph.py:720-762`). It also strips tracers from the run's own and inherited callbacks. But LangChain decides whether to trace by first checking the tracer that `tracing_v2_enabled()` sets (`tracing_v2_callback_var`, `langchain_core/tracers/context.py:141-144`). Only after that does it look at the setting `tracing_context` changes. While setting up the run's callbacks it then adds that tracer (`langchain_core/callbacks/manager.py:2483-2515`), after the stripping has already happened. Nothing in `src/` resets that variable.
- **Effect:** the run's inputs, statement data among them, go to LangSmith under the lock. R29 says LangSmith's own tracing is off under the lock whatever the environment says, so R29 fails, and P18 with it.
- **No test covers this:** the existing tracer tests use environment variables, tracers passed in callbacks, and inherited runnable callbacks.
- **Likely fix:** under the lock, also set `tracing_v2_callback_var` to None for the run, and reset it afterwards.
