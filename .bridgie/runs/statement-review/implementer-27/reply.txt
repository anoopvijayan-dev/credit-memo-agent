All eight verify-09 findings were reproduced and fixed, and every gate passes. The task branch had been reset to the current base, so I first re-applied the earlier T17 attempt (83ac630) and resolved its conflicts with the CMA_RULESET work, keeping both.

**What changed:**
- **Retries off:** both hosted clients are built with SDK retries off, so every HTTP request is one call that checks the lock first.
- **One lock reading per run:** a run reads `firm.yaml` once at its start. That reading decides whether the client can be built and whether each hosted request is sent, and the evidence records it, labelled as read at run start.
- **MCP server:** a saved ASGI app (one made while the lock was off and served later) now checks the lock when the server starts it. Under the lock that start-up fails before uvicorn opens a socket, which I tested with real uvicorn. Each connection is also refused with a 503 or a WebSocket close.
- **Prompt:** the policy name and the separate "Overall policy outcome" line are gone; the overall outcome is now a row of the rule table. A redraft adds only one line of metric and rule ids that are in the tables, so nothing the model wrote goes back to it.
- **Monzo import:** a provider transaction ID that starts with `-`, `=`, `+`, `@`, `.` or `:` is refused instead of being written into the CSV.
- **`firm.yaml` parsing:** a file that isn't valid UTF-8, or that gives a key twice, is refused with a named error, and the CLI exits 2.
- **Tests:** the P5 and P18 tests are now marked `invariants` and named `test_p5_*` and `test_p18_*`, so the runner runs them by name. I renamed the old "migration" test to say it checks record formatting only, not resuming an old checkpoint.

**Gate results:** ruff clean, 537 passed in the full suite, 140 in invariants, 31 in contracts, 79 in dual_run, and 9/9 offline evals grounded. To check the new tests catch real regressions, I temporarily turned retries back on and removed the ASGI wrapper. Both retry tests failed, and the uvicorn test started serving instead of exiting. Both changes are reverted.

**Things to know:**
- **Lock timing:** I read "firm.yaml read once per run" literally, so a lock turned on partway through a run only takes effect from the next run. A hosted request made outside a run still reads `firm.yaml` itself.
- **Test environment:** I ran everything with `PYTHONPATH=src` because the shared environment's install of `cma` points at the T03 worktree. The runner should install this worktree with `pip install -e ".[dev,mcp,durable,llm]"`.
- **P5 gap:** nothing in the code loads a case profile into the graph yet (that's T13's case store). The P5 test puts the profile's names into every description and the account name, and passes the profile's VAT stagger, which is all a profile can reach today.
- **Not committed:** the changes are staged in the worktree but not committed.
