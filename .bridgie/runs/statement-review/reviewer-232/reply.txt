**Minor findings:**
1. **A refusal can name the wrong line.** `write_statement` assumes each statement row is one line of the file (`contract.py:109-111, 127`). But a Monzo Type cell containing a line break is not collapsed by `describe()` (`monzo.py:155`). That makes the description a quoted field spanning two lines, so every later row shifts down a line. If the loader then refuses a later row, the message points at a different row of the export.
   - Repro: an export whose rows sort as B (Type `"Odd\nType"`), C, A (dated 01/01/2099), D. The loader reports statement line 5, which maps to D's line instead of A's.
2. **Refusals no longer say what's wrong.** A loader refusal of the importer's output (for example a future-dated row) now reads only `other problems on line N`. `contract.py:13-15` promises "what is wrong", and the test asserts that "future" is *not* in the message. `cma case import` of a statement CSV has the same loss: the old message named each problem.
3. **One cell value still reaches a refusal.** A Monzo header with a repeated column name prints that name (`monzo.py:177-179`), which is text from the file. The producer disclosed this. `cma case import` of a CSV already drops it.
