I went through T13's checklists and closed one gap. Running a `cma case` command against a case root the file system couldn't create printed a raw Python traceback and exited 1. It now prints a "Refused." line naming the error and exits 2. The fix is a few lines in `src/cma/cli.py`, plus one test in `tests/test_case_store.py`. Afterwards ruff, compileall and the full suite passed (1877 tests, 51 of them in `tests/test_case_store.py`).

The two major findings from attempt 1 no longer reproduce at the current head (81eb812):
- **Overlapping profile changes:** the profile is now read and changed while the case is held. Two overlapping changes both survive, and a refused change puts back the last recorded profile.
- **An import missing from the log:** whether a file was already imported is now decided from the case log, so a file whose log entry never got written is recorded when it is imported again.

Five gaps are left for the owner in `notes`; none is fixed in code:
1. A crash mid-import can leave a temporary work folder holding a copy of the export inside the case folder. It is owner-only, but nothing cleans it up.
2. Copies of the input file left in `inputs/` by a crashed import are never removed if that file isn't imported again.
3. After a save that isn't confirmed whose entry a later repair drops, `case.yaml` can differ from the last logged profile hash. `cma case check` doesn't compare the two.
4. Re-importing a file reports the account name passed this time, not the one it was first imported under. This is cosmetic.
5. There is no alert beyond the case log entries and non-zero exits, which matches the design's local-only approach. The repo has no changelog file to update.
