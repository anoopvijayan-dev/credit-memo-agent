I went through every checklist line for the T15 purge and fixed two real failure gaps in `src/cma/store.py`. Lint, compile, the full suite (1929 passed) and the offline evals (9/9 memos fully grounded) all pass.

**Gaps fixed:**
1. **A purge could lose its ledger line.** The files were deleted before the ledger line was written, so a failed write (a full disk, say) left nothing to retry: running the purge again answered "no case" and nothing was ever recorded. Now the emptied `cases/.purging-<id>` folder stays until the line is written. The error says "purge again", and running it again records the purge.
2. **Two purges at once could recreate the case and record it twice.** If a second purge found the case before the first moved it, taking the case lock recreated the deleted folder, and a second ledger line was written for the same case. Now the lock files are only made for a case that lacks them, the case is re-checked once the purge holds it, and the ledger gets a line only if it has none for that case.

I wrote a small script to make both failures happen before the fix, and added three regression tests to `tests/test_case_purge.py`.

**Left for the owner:**
- Two purges that both start after the first has moved the folder can still both write a line. Stopping that needs a lock on the ledger file, which is a design choice for a firm-wide file.
- A purge refused because another window holds the case prints "Not recorded." (exit 4). That wording was written for saves.
- The "who" in the ledger is the operating-system user name, which environment settings can change. It is a record, not proof of identity.
- Nothing flags a purge left unfinished; leftover `.purging-<id>` folders are the only sign.
