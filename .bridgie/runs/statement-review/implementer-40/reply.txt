T15 is built: `cma case purge` deletes the whole case folder and adds one line to `purge_ledger.jsonl` holding only the case id, the time and who purged it. The new purge tests pass (9), ruff and compileall are clean, and the full suite passes (1926 tests). I haven't committed anything; the changes are in the T15 worktree for the runner.

- **How it works:** `store.purge_case` first takes the case as a writer, so a save running in another window finishes first or the purge is refused. While it holds the case it renames the folder to `cases/.purging-<id>`, so no other command can find the case. It then deletes everything, read-only input files included. Only after every file is gone does it append the ledger line, as `case`, `purged_at` (UTC) and `by`. The ledger file is owner-only (0600) and synced to disk after each line.
- **Command:** `cma case purge CASE` asks before deleting, and `--yes` skips the question. An unknown or malformed id is refused with exit 2 and nothing is written to the ledger. Answering no deletes nothing (exit 1).
- **Interrupted purge:** if deletion fails part-way, the `.purging-<id>` folder is left behind with no ledger line. Running the same purge again deletes what is left and then records it.
- **Tests:** they check that no file under the case root is named by the purged id and that another case is untouched. They also check that the ledger line has exactly those three keys and contains none of the director's name, the label, the transaction descriptions or the amounts. Other tests cover purging while another writer holds the case and purging a case whose log is broken.
- **Who purged it:** recorded as the operating-system user, the same way sign-off records it. No typed name is asked for, so nothing beyond the three fields is stored.
- **Windows:** a folder whose lock files are open can't be renamed there, so the rename happens just after the writer lock is released. A writer that slips into that gap finds its lock files moved and refuses its next step. CI runs on Linux, so this path hasn't been tested on Windows.
- **Case log:** purge writes nothing to the case's own log, because that log is deleted with the case. The ledger is the only record.
