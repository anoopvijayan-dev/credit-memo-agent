**What `cma case preview CASE` does:**
- **Memo field map:** the default (`src/cma/memo_fields/memo_fields.yaml`) is the reply's 13 fields in order, with M18 directly after M2 in the turnover field. A firm's own `memo_fields.yaml` replaces it, and a malformed map is refused, naming the problem.
- **Section text:** each field's sentences are filled in from the figures layer, money to the whole pound, each figure followed by its id ("£751 [M2]"). Business details, loan request, credit history, key risks and the recommendation are marked for the underwriter and left empty (R27, R24).
- **Policy check:** while `show_policy_verdict` is on, a section after the memo fields starts with the illustrative label, then the overall outcome and each rule. Each rule line gives the figure tagged `[Mn]` and the threshold tagged `[Rn]` after a limit word. With the setting off, the text has no outcome, rule result or `[Rn]` tag.
- **Demo stamp:** a demo case gets a stamp saying it demonstrates the mechanism and is not an applicant file.
- **Grounding guard:** the guard checks each account's text against that account's own figures and policy result. The command exits 1 and lists the findings when the text fails, and 2 when the case can't be previewed.
- **Snapshot hash:** it covers every input R22 lists. The tests change each one in turn and confirm the hash changes each time.
- **What it writes:** no file, only one `preview` entry in the case log. The entry holds hashes and counts, never names, descriptions or override reasons.

**Choices worth knowing:**
- **Rule descriptions:** the policy-check lines don't quote them, because they contain untagged numbers ("at least 12 months") that the guard would reject.
- **Snapshot gaps:** firm rules aren't built yet (T37), so the snapshot hashes `firm_rules.yaml`'s bytes, or null when the file is absent. The case-log head is left out, because R22 doesn't list it and the preview's own entry would change it.
- **Failed guard:** a preview that fails the guard is still recorded, with `grounded: false`. T27's sign-off needs to refuse it.
- **Digit-only account keys:** an account key made only of digits would be read by the guard as an untagged number, so that preview would report itself as failing. This only matters for multi-account cases (Tier 2).
