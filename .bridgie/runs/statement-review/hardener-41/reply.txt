I hardened T18 and found two gaps in the review server, both now fixed with tests. On the latest run, the review-server tests (48), ruff and compileall pass. The full suite passed (1998) and so did the contracts tier (557), both run with the second fix in place.

**The two fixes:**
- **A request body read as a second request.** The server never reads a request body. Over a kept-alive connection, a POST's unread body was parsed as a second request: a probe got two responses for one POST. The second request still had to pass the token and Host checks, so nothing got past them. Now any request that isn't a GET, or that carries a body, closes its connection after one answer.
- **No timeout on connections.** An idle or half-sent request could hold a server thread forever. Connections now close after 30 seconds of silence.

**Other checks, all passing:** every route and method requires the token, the exact loopback Host and a same-origin request. Only the bundled files are served, under a strict content security policy with no inline script and no CORS headers. The token never reaches a log, and no new dependency was added. The server only reads: it writes nothing to the case, so there is nothing to migrate or roll back.

**Gaps for the owner:**
- I couldn't confirm that the page's files (`src/cma/review/static/`) end up in the built wheel. hatchling isn't installed here, so the wheel build failed. A check that loads them from an installed wheel would settle it.
- The repo has no changelog, so no release note was written.
- Refused requests aren't counted or logged anywhere; the request log is off to keep the token out of it. A signal for repeated refusals needs a design decision.
