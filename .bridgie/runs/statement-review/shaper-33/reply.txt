**What P5 now says.** The prompt has to carry the statement period, the figures and the policy table (R30 allows it). Some of what those carry is decided by the case: the period's first and last dates, each figure's value and each rule's outcome. A description or profile string that matches one of them is the case's own figure, not leaked text, so P5 doesn't count it. Taken together with revision 32's scope, P5 now asks one thing: a prompt holds nothing except the tool's own text and the values the case decides. Any other description or profile text in a prompt still fails P5.

**Two readings I added beyond D315's words, so the next review can't open a new gap:**
- A part of a value, or a value with its label beside it, is also exempt (`2026-09` inside `2026-09-30`, or `Period: 2026-09-30`). If only exact whole values were exempt, `2026-09` in a description would fail P5 on every prompt for that statement, and no code change could prevent it.
- Some text in the prompt is the tool's own but wasn't on revision 32's list: the line labels, the fixed sentences used for a figure's method and a rule's sentence, and the placeholders a custom rule shows instead of its own text, like `(custom rule)`. These now count as the tool's text too.
