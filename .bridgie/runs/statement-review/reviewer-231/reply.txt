**What meets R33:**

- **New token per launch:** each start makes a fresh random token.
- **Checks before anything is served:** every route and method checks the Host, Origin and token first.
- **Bundled files only:** the server serves only the files bundled in the package, matched exactly against a list made at start-up.
- **Called by production code:** `cma review` starts the server and prints the URL with its token.

The runner's full-suite and contracts logs both show all 49 tests in `tests/test_review_server.py` passed.

**Minor findings:**
1. **Token can leak to other users on the machine** (`src/cma/cli.py:743`). Opening the browser passes the URL, token included, as a command-line argument. On a shared machine, other users can read it with `ps` and then read the case through the workspace.
2. **Some error responses skip the security headers** (`src/cma/review/server.py:93`). When the standard library rejects a malformed request before the server's own checks run (bad request line, unknown method, overlong header), its error page carries no CSP or other security headers. No case data leaks, but "every response carries a strict CSP" isn't true for these.
