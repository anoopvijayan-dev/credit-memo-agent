**How a sign-off works.** It holds the case for the whole sign-off and checks the whole log first. If the chain is broken or the last entry is incomplete, it is refused naming the first bad entry (exit 3 in the CLI).

It then finds the preview the underwriter signed by its snapshot, reads the case's inputs again and compares them with what that preview recorded. Any change is refused, saying what changed, for example "the override log (it held 0 entries, it now holds 1)" or "the statement for account main changed". It also refuses when the figures don't reconcile, when the text fails the grounding guard, or when that snapshot's pack is already written.

**What it writes.** `memo.md` (exactly the preview's text) and `evidence.json` are written into a temporary `packs/.part-*` folder, synced, then renamed to `packs/<snapshot>`. The pack is never overwritten. Two log entries, `pack_written` then `signed_off`, are appended only after the rename. Leftover `.part-*` folders from a crash are removed at the start of the next sign-off.

**Wording.** Both places say "Sign off the figures" and state that this does not approve the loan. `cma case sign` asks for a typed name and a confirmation and has no `--yes`. The workspace has a "Preview the pack" button, a preview page with the sign-off form, and matching data endpoints.

Things to know:
- **Second log entry not recorded.** If the file system fails between the two log entries, the pack stays with `pack_written` recorded but no `signed_off`. A retry for that snapshot is then refused as already written, and the underwriter has to preview again to get a new snapshot.
- **`evidence.json` is a first version.** T25 owns the full evidence schema and `monthly.csv`; T26 owns `record.html`.
- **I changed an existing test.** The escaping test helper in `tests/test_workspace_summary.py` lists which form targets the page may contain. I added `/preview` to that list, since the new button is meant to be there.
- **The sign-off is not in `memo.md`.** The name and time would put numbers in the memo that the grounding guard would reject. They are in `evidence.json` and the case log instead.
