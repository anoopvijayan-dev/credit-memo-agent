**T39 fails review: P10 passes, R46 fails because of one major defect. I also found three minor issues.** I couldn't run probe scripts here (the permission was denied), so the repros below are traced through the code, not executed. Writing `evidence.json` to the run directory was also denied, so the evidence is in the block at the end.

**P10 passes.** Before writing anything, `pseudonymise_statement` compares the copy with the original under both v1 and v2 (`differs()`, `pseudonymise.py:356-375`). It checks every line's category, rule and reversal link, every figure (buckets included), the monthly summary and the indicators, and refuses if anything differs. The runner's full run shows all `test_p10_*` tests passing, including the 18 synthetic archetype/risk/feature combinations (`specified-3.log:1914-1944`).

**R46 fails.** The command is wired into the CLI, the profile is tokenised, the label is written into the copy, and ids, dates, amounts and balances are copied unchanged. But some business names survive:
- At `pseudonymise.py:288`, any word that even partly overlaps text a rule reads is kept whole.
- Several rule patterns can match inside a longer word, because they have no word boundary in front: `FINANCE\b` (v1 and v2), plus `PAYROLL|SALARIES` and `DIVIDEND` (v1 only).
- So names like GREENFINANCE, SMITHFINANCE and BRIGHTPAYROLL come out unchanged, in the statement and in the profile (`keep_words`, line 308).
- This is the same kind of defect as the earlier "Greenfield Capital Ltd kept whole" finding. The fix in f9351f5 only handled whole-word matches, and no test covers a match inside a word.
- A fix that keeps P10 exists: a token like `QZAAAAAAFINANCE` would still be read the same way by both rule tables.

**Minor findings:**
- **Valid statements refused over spacing** (`pseudonymise.py:284`). Two spellings of a profile name that differ only in spacing get different tokens, but the figures treat them as one payer. With a business name on customer-transfer lines, the largest-payer share (M15) changes in the copy, so the command refuses and writes nothing.
- **The firm's thresholds file is ignored by default** (`cli.py:687`). Without `--thresholds`, the copy is checked against the packaged thresholds, while the workspace uses the firm's file. A gambling operator the firm added gets tokenised, and that indicator disappears when the copy is opened in the firm's case.
- **Unproven claims.** The "deterministic" and "about 5 ms per line" claims cite `scratchpad/perf.py`, which no runner tier ran. A test the runner did run covers determinism; the performance figure has no proof.
