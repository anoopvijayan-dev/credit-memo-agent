I checked T32's commit (b6ea52f) against every checklist and changed no code. The change works: ruff is clean and the full suite passes (2038 tests). One gap on the data path still needs your decision.

**What holds:**
- **Same file imported twice (R39, P9):** a second import under any account name leaves every file in the case folder and the case log head unchanged, for both CSV and Monzo files. A test marked `invariants` proves it (2 runs passed).
- **Same account imported twice (R40):** an account whose period overlaps an existing one and shares most of its (date, amount) pairs is refused, and nothing is written. The refusal names no description or amount. Three cases that should go through are added: few shared pairs, no overlap, and own-account transfers with opposite signs (4 tests marked `contracts` passed).
- **Concurrency:** the R40 check runs while the case is held and before any file is written.
- **Security:** there is no new command or dependency.
- **Migration, performance:** these don't apply. Nothing stored changes, the check runs only at import and is linear in lines, and rolling back means reverting b6ea52f.

**Gaps (in `notes`):**
1. **R40 fails open.** If the existing account's statement file can't be read or loaded, the check skips it, and a duplicate account gets in. A test script I wrote reproduced this: I overwrote `statements/main.csv` with garbage, and the duplicate was added. There are two possible fixes:
   - refuse the import and report the case as damaged;
   - check the file against the hash stored in its import entry and refuse if they differ.

   Either one changes behaviour, so I left it to you.
2. **The design contradicts itself.** Its Failure modes row for R39 says the log notes a repeated import. P9 and the task title say the log head stays the same. The build follows P9, so the design row should be corrected. The only sign of a repeated or refused import is the CLI message or exit code 2.
3. **The threshold for "most".** It is more than half of the new statement's lines in the overlap, so a one-line overlap that matches is refused. R40's wording allows this, but the design should say so.
