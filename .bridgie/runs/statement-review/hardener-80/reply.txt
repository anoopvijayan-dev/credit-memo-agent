I walked every checklist for T40 and found one real failure, now fixed. If one case broke in a way nothing planned for, `cma report` stopped with a traceback and never listed the other cases. Now that case shows as "could not be read", the rest are still reported, and the command exits 1. The error text is not printed, because it could quote a statement.

**What I checked:**
- **Read-only:** the report changes no file in the case root. I hashed every file before and after two runs and nothing changed.
- **Personal data:** no names, descriptions, amounts, "£" or durations appear, in plain output or in `--json`. The new test also checks that the broken case's error text stays out.
- **Exit code:** it exits 1 when a case is untraced, unreconciled or cannot be read, and 0 otherwise, including when there are no cases.
- **Docs:** I added a `cma report` entry to the README beside `cma case check`.
- **Tests:** the full suite passes (3004 tests), and so do ruff on `src`, `tests` and `evals`, and `compileall`.
- **Not applicable:** performance, a feature flag, rollback and alerts. It is a new local command that only reads files and runs only when invoked.
