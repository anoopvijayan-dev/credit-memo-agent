The P14 failure from attempt 1 is fixed. I changed no code: the fix was already committed at `0ceaeb1`, and I verified it.

**The fix.** When the grounding guard reads an account's text, the "Account {key}" labels are replaced with spaces of the same length. The guard still reads every other character. So an account key like `2`, `hsbc-1` or `2026` no longer gets read as a number with no figure id.

**The test catches the bug.** The new P14 test uses 8 account keys with digits or number words. With the old label behaviour patched back in, all 8 fail; at `0ceaeb1` all 8 pass, with the policy check both shown and hidden.

- **P20:** the label is the policy-check section's first line, and the recommendation stays blank. With `show_policy_verdict` off, no outcome appears anywhere.
