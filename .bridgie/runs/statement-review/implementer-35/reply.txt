T08 is built and committed as `6b3724a` on the T08 branch. The full suite passes (1368 tests), and so do ruff, compileall and the offline evals (9/9 memos grounded).

- **Indicators:** `src/cma/indicators.py` raises all eight kinds: large credit, single cash deposit, cash-heavy month, cash round trip, gambling, returned DD, overdrawn run and irregular acquirer credit. Each one lists its lines, the threshold that fired and an illustrative flag, plus a one-line reason that never quotes a description.
- **Thresholds file:** `src/cma/thresholds/indicators.yaml` ships the cash values decided in D35 (£2,500 for a single deposit, 50% of a month's trading receipts) and the design's 7 days and 10% for the round trip. Money is read exactly as whole pence and compared in pence. Shares and multiples are compared as exact fractions.
- **Validation:** a malformed file is refused with `ThresholdsError` naming the line. That covers bad YAML, a section or key that is missing, unknown or given twice, and a value of the wrong kind (such as a fraction of a penny or a share above 100).
- **`cma run` and the evidence record:** `cma run` takes a new `--thresholds FILE` option, which defaults to the packaged file. A malformed file exits 2 naming its line. The evidence record now has `thresholds` (source, hash, which values are still shipped) and `indicators`. I regenerated the committed example's evidence the same way and added a test that checks it.
- **Tests:** one fixture per kind is in `tests/test_indicators.py`, each built just either side of its threshold.

The design left some choices open, and I made these (`notes` in claim.json has all of them):
- "Typical trading receipts" is the median trading-receipts credit.
- An acquirer credit is "irregular" when it is at least 3 times, or at most a third of, that acquirer's median credit, once the acquirer has 3 or more credits. The design's other cue, an acquirer name arriving by Faster Payment, is not built.
- No rule table lists gambling operators, so the list lives in the thresholds file.
- The round trip spots a withdrawal by the v2 `cash_withdrawal` rule, so it never fires under v1.

Not covered by this task: the judgement-queue half of P19 and the indicator truth for P17 belong to other tasks. There is no firm-config (`firm.yaml`) path for thresholds yet, so a firm's own file only reaches `cma run` through `--thresholds`.
