I've built `cma pseudonymise` and committed it as 766e408 on the T39 branch. The copy it writes gives exactly the same figures as the original, under both rule tables. The full suite passes (2997 tests), and ruff and compileall are clean.

**What it does:** `cma pseudonymise FILE --format F --out DIR [--profile CASE]` runs the file through the importer for its format and writes a copy into a new folder that only its owner can read:
- the statement, with names and account numbers replaced by consistent tokens;
- the case profile, tokenised the same way;
- a label file and a manifest, both saying it is pseudonymised personal data, not anonymous data.

The token mapping is never written. Every id, date, amount and balance is kept exactly. It refuses to write into a folder that already has files in it.

**How it keeps the figures the same (P10):**
- **Kept as written:** anything the v1 or v2 rule tables recognise, such as STRIPE, IWOCA, HMRC, UNPAID DD and invoice references. So are the gambling operators and the bank wording the counterparty matching relies on (FPS, BACS, DD).
- **Profile names:** directors, shareholders, own accounts and the business name are found in the descriptions the same way the categoriser finds them. Each becomes one token, in the profile and in every description that contains it. A director's name inside an own-account name still matches both.
- **Everything else:** each distinct word gets its own token, so lines that named the same payer still group together.
- **Check before writing:** the copy is categorised and its figures computed under both tables, then compared line by line, figure by figure, month by month and indicator by indicator. Any difference refuses the copy and nothing is written.

Tests marked `invariants` cover every synthetic business type and risk level, with and without the extra features, plus hand-built edge cases. Tests marked `contracts` cover the command itself, including a Monzo export.

**Limits:**
- **Firm rules and overrides:** P10 is checked without them. A firm rule's pattern can name a payer the copy has replaced, so it may no longer match.
- **Names that look like an institution:** a profile name that holds recognised wording, such as a director called IWOCA, is left as it is. The manifest counts how many were kept.
- **One file at a time:** the command takes one statement, so there is no check across a case's several accounts.
- **Upper case:** descriptions in the copy are upper-cased.
