**What changed, as D141 asked.** No ids, forms or risk tags change.
- **R4:**
  - A v2 pattern may carry an anchor (`^`, `$`, `\A`, `\Z`) only on the bank's returned-payment code (D137).
  - Only a match that itself counts can set another aside inside its longer phrase. This is verify-71's case: with those two table edits, FPS CASH DEPOSIT STRIPE is ambiguous, not a cash deposit.
- **R42:** if a save's read-back fails, the save takes back the head record it published, as long as that record is still its own. Its entry is then past the recorded entries, the way a crash leaves it.
- **R43 and P15:** a reader's read counts only while the lock files it holds are still the case's lock files. A read across one that was removed or replaced is taken again, and nothing is claimed from it. D141 says "replaced". I also wrote "removed", because R42 already says "removed or replaced" and the f5436bb code treats a missing file the same way.

The owner has already built all four (T03: 5c9a5bd and 2c72469; T12: f5436bb). None has been reviewed yet.

**Gaps I found in those commits:**
- **T03, R4 judged per match vs per rule.** 5c9a5bd decides which matches count rule by rule. Take a table that adds FPS STRIPE CASH DEPOSIT to the rail list and STRIPE CASH DEPOSIT to the gateway list. The line FPS STRIPE CASH DEPOSIT REF STRIPE then becomes a card settlement in trading receipts, even though R4 makes a rail with cash wording ambiguous. This happens because the trailing STRIPE keeps the gateway rule counting. Judged per match, as R4 defines a match, the credit is ambiguous.
- **T12, one read is not re-checked.** When a check finds the gate busy and the case lock free, it reads holding only the case lock and never checks that lock file afterwards (`src/cma/case.py:527-533`). R43 now asks for that check.
- **T12, the take-back can fail too.** Then the save is told "not recorded" but its entry stays among the recorded entries, which P15's wording rules out.
- **T12, a gate replaced before a read.** A writer that passed the old gate can still take the case, so a reader may report "being saved" over an incomplete entry. Nothing the reader holds can show this.

These four gaps lead to the three questions below. Each has a design default.

Still open in T12: leftover staging files after a failed write, the "nothing was written" message after a partial line, and nine tests that are marked as invariants but not named p15.
